AUDITORÍA V1.15 — IDENTIDAD CLOUD Y ADMINISTRACIÓN

ARQUITECTURA
- Directorio de usuarios: `marvel-marathon-profiles-v1`.
- Estado Marvel existente: `marvel-marathon-accounts-v90`.
- Autenticación: Function `marvel-profile` + cookie HttpOnly firmada.
- Estado: Function `marvel-state`, autorización por sesión USER.
- Admin: perfil virtual `marvel-admin-root`; token validado únicamente en servidor.

MODELO DE IDENTIDAD
- ADMIN visible: `administrador1 × administrador2`.
- Juanjo × María: `jm-user`, USER normal, separado de ADMIN/root.
- La autoridad para crear/eliminar perfiles se comprueba server-side por rol ADMIN.
- Los campos enviados desde el navegador no pueden elevar una cuenta a ADMIN.

SEGURIDAD
- PIN nuevos: scrypt + pepper secreto server-side.
- PIN migrados: PBKDF2 legado solo durante transición; upgrade a scrypt al primer login válido.
- Session secret, profile pepper y PIN de bootstrap nunca se envían al cliente.
- Cookie: HttpOnly + Secure + SameSite=Lax.
- Bloqueo tras 5 PIN incorrectos durante 10 minutos.
- Cambiar PIN incrementa `sessionVersion` y revoca las sesiones previas de ese usuario.
- Rotar `MARVEL_ROOT_ADMIN_TOKEN` invalida sesiones ADMIN anteriores mediante huella del token.
- El Service Worker no intercepta ni cachea `/api/marvel-profile` ni `/api/marvel-state`.
- El endpoint de estado ignora cualquier `X-Marvel-Account-Key` enviado por el navegador y resuelve el estado desde la sesión autenticada.

MIGRACIÓN
- V1.14 puede enviar al servidor su verificador PBKDF2, snapshot local y cloudKey existente solo dentro de una sesión ADMIN.
- Juanjo × María usa `MARVEL_JUANJO_MARIA_PIN` únicamente para bootstrap/preservación de la identidad Cloud V131.
- Si existe la antigua identidad `juanjo-maria-root`, se remapea a `jm-user` como USER y se elimina el registro heredado ADMIN.
- El bootstrap de Juanjo × María es de una sola inicialización y no reaparece tras un renombrado/borrado intencional.
